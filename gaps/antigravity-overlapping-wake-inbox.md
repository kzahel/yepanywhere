# Antigravity overlapping wakes need native inbox evidence

Known detached work and observed root replies keep the owner retained
through a fresh, fully idle native summary. That boundary has been
qualified with a single scheduled wake and a child's asynchronous report
against the scripted model. It cannot distinguish a settled reply from
another autonomous wake waiting in the native inbox if both tasks have
already cleared their visible work items. An untracked wake can also be
invisible before its first ACP output. If an unidentified reply's native
timestamp predates the first received frame, YA keeps it unverified until
a later successful foreground turn supplies a fresh settlement boundary.

Qualify unread waking messages and trailing native system steps on the
pinned and candidate runtimes. Run with two task completions during the
same detached reply and verify that a patient item, idle reap, and scheduled
reload remain held through the final reply. Compare the bounded inbox
checks documented in the [T3 Code reference](../topics/antigravity.md#t3-code-reference--2026-11-22).
